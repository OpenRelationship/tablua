* Notes
The harness's own gates (arock issue #1, M5), written once by us as keyword scenarios: each says which move is
held back in which state, and why, in the words of the behaviour model (Tablua's effects, recorded from the
harness's telemetry). The gates live in Lua (world/world.lua, facts.lua); this file states them, and each
=# because:= line is checked against every recorded run (=just tool eval build gates=): the move, the state and
the effect the gate expects it to bring, more or less often than steps at all. A gate whose reason does not hold
is the first to be retired, and every gate is retired only through an A/B: each scenario's =# gate:= names the
gate in world/gates.lua that a run turns off with gates_off (AROCK_GATES_OFF in Arock's eval), kept as tablua_gate.

A because line: =# because: <move> | <given> | <effect> | more|less=, the given a list of =stage <s>=,
=<n>+ stalls=, =last step <outcome>=, =last move <move>= or =any=, joined with commas; or
=# because: unmeasured: <why>= where no effect the harness records can speak to the gate's reason.
